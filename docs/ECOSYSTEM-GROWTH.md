# DSH 茶歇间：生态增长与发布作战卡

茶歇间不需要和所有 DSH 插件竞争。它最容易被记住的角色是：**一个等任务时打开就能玩的、有审美、有陪伴感的本地游戏入口。**

## 从近期生态项目借鉴什么

生态里更容易被采用的项目通常有三个共同点：一句话能说清楚、安装后马上得到结果、README 对隐私和边界说得诚实。`dsh-conversation-exporter` 解决单一整理痛点，`dsh-find-plugin` 把发现和安装合并，`awesome-dsh-plugin` 用可验证的条目降低选择成本；`grix` 则把“继续和 Agent 工作”包装成跨设备的具体场景。

茶歇间的传播句应该固定为：

> 编译、测试、长任务之间，打开 DSH 茶歇间，随时玩一局，收起后从原处继续。

不要把项目讲成“小游戏合集”。用户真正购买的是一个更舒服的等待状态：没有账号、广告、遥测和联网对战；模型不可用时牌局仍然可玩；存档、陪伴角色和任务提醒都不打断主任务。

## 已经在项目内完成的增长基础设施

- 大厅使用原创月下港湾主视觉，并在构建时内嵌，用户不需要等待远程图片。
- 特色游戏“港湾对决”拥有带艺术封面的重点卡片，其他游戏保留统一的轻量卡片节奏。
- 入口、首屏、卡片、悬停、键盘焦点和窄屏布局统一了视觉语言。
- README 已经明确写出“模型不可用也能玩”和“本地数据边界”，这些是信任资产。

## 发布动作

1. 录一个 20–30 秒 GIF：打开茶歇间 → 选择港湾对决 → 出第一张牌 → 收起 → 重新打开继续。
2. 发布一张大厅截图和一张游戏中截图，不要只发代码仓库截图。
3. 在 `awesome-dsh-plugin` 提交前，确保 `dsh.bundle`、安装命令、版本和 README 已经完全一致。
4. 用一个真实场景发帖：等待测试、等待 Agent、等待编译时，为什么“可随时收起且不丢局”比功能数量重要。
5. 把首批 Issue 只分成 `first-run`、`gameplay`、`visual`、`privacy` 四类，降低贡献者进入门槛。

## 可直接使用的短文案

```text
DSH 茶歇间：给等待编译、测试和 Agent 的几分钟，一间真正能随时收起的本地游戏馆。

港湾对决、鲸牌茶歇、港湾配对；统一的月下港湾美学，按游戏独立存档。
澜音可以陪你聊两句，但模型断开时牌局照样能玩。

无账号、无广告、无遥测、无联网对战。打开即玩，收起后接着你的任务。
```

## 诚实边界

增长的目标是让对的人快速完成第一次游戏，不是制造虚假的稀缺感或夸大生态地位。先把首次安装、第一次开局、第一次恢复存档做得可靠，再考虑更多游戏、排行榜或社交功能。
